HTTP Methods We Support

What the parser understands · September 2026

Every request line begins with a method — a verb that tells the server what the client wants to do. Our current server implements GET and HEAD, and rejects anything else as unimplemented.

GET

The workhorse of the web. GET asks the server to retrieve a resource. In our implementation it reads the requested file from the web root and returns it with the proper Content-Type header. Because GET is a safe, read-only operation, browsers and caches rely on it heavily for loading pages, stylesheets, and images.

HEAD

Identical to GET, except the server omits the response body. It is handy for checking whether a resource exists, reading its headers, or measuring a response before downloading it. Our HTTPParser recognizes HEAD just like GET.

"Supporting HEAD for free is a nice side effect of keeping GET simple."

Not Yet Implemented

Methods like POST, PUT, and DELETE are part of the roadmap. They introduce the need for an HTTP request body — and along with it, careful handling of Content-Length and Content-Type on the request side.
