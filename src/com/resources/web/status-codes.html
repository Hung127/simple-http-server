HTTP Status Codes

The language of outcomes · September 2026

After processing a request, the server returns a three-digit status code that tells the client how it went. Our server models these in the HTTPStatusCode enum, each carrying a numeric code and a human-readable message.

Success: 200, 201

Everything worked. 200 Success is returned for static files, list/fetch/update/delete API calls; 201 Created accompanies a successful POST.

Client Errors: 400, 404, 413, 414

These mean the request itself was malformed or impossible. 400 Bad Request appears when the request line or headers are invalid — or when an API call is missing a required JSON field. 404 Not Found covers missing files and unknown API routes. 413 Content Too Large guards against oversized request bodies, while 414 URI Too Long caps excessive request targets.

Server Errors: 500, 501, 505

These indicate the server could not fulfill an otherwise valid request. 500 Internal Server Error flags an unexpected failure handling a file. 501 Not Implemented is returned for methods we do not support. 505 HTTP Version Not Supported rejects requests from an unknown protocol version.

"A good status code turns a vague failure into an actionable one."
