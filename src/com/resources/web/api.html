REST API

The Todo REST API

Routing + JSON, all served by one hand-written server · September 2026

Once routing was in place, our server grew a small REST API. Requests whose target begins with /api/ are handed to a router instead of the file system; the router matches method and path, extracts path variables, parses the JSON body, and dispatches to an endpoint handler.

Endpoints

Method Path Purpose Success
GET /api/todos List all todos 200
GET /api/todos/{id} Fetch a single todo 200
POST /api/todos Create a todo 201
PUT /api/todos/{id} Update a todo (partial) 200
DELETE /api/todos/{id} Delete a todo 200 
// a todo
{
    "id": 1,
    "title": "learn http",
    "completed": false
}

Try It With curl

The server listens on port 8080 and seeds three todos, so ids 1–3 exist at startup.

List all todos:

curl http://localhost:8080/api/todos

Fetch one:

curl http://localhost:8080/api/todos/1

Create (the body is parsed as JSON):

curl -X POST http://localhost:8080/api/todos \
  -H 'Content-Type: application/json' \
  -d '{"title":"learn curl","completed":false}'

Update — title, completed, or both, partial updates are fine:

curl -X PUT http://localhost:8080/api/todos/1 \
  -H 'Content-Type: application/json' \
  -d '{"title":"learn curl thoroughly"}'

Delete (the parser reads bodies for non-GET methods, so send a length):

curl -X DELETE http://localhost:8080/api/todos/1 -H 'Content-Length: 0'
"The same socket code serves both a static site and a JSON API — the only difference is where the request is routed."

Unmatched /api/ paths return 404 with an HTML error page, and malformed API calls return a JSON error object:

{"error":"Bad Request","message":"Field 'title' is required","statusCode":400}

Served by a hand-written Java HTTP server. New to the methods? See HTTP Methods.
